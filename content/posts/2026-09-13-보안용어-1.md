# SSO (Single Sign On)  
![](1_sso_waifu2x_x2_n-1.webp)
- 한 번의 인증으로, 여러 서비스에 다시 로그인 하지 않고도 해당 서비스들에 접근할 수 있게 해주는 **인증 시스템**이다.
- 구글 계정 하나로 Youtube, Gmail, Google Drive등의 서비스가 사용 가능한 것과 같이, 중앙 계정 하나로 다른 서비스를 이용 가능하다.
- 주요 동작 흐름은 다음과 같다.
	- 중앙 인증 서버에서 사용자가 인증 완료시 Token이나 Assertion을 증명 수단으로 발급한다.
	- 각 서비스에서 Token이나 Assertion을 검증하여 사용자의 접근을 허용한다.
- 하나의 계정으로 각 서비스의 이용이 가능하다보니 사용자의 서비스 접근 편의성이 향상되고, 계정 관리가 용이해지는 이점이 있다.

<br>


# MFA (Multi Factor Authentication)  
![](2_mfa_waifu2x_x2_n-1.webp)

- 서로 다른 인증 요소를 조합하여, 본인임을 증명하는 **인증 방식**이다.
- 어떤 서비스에 계정 정보로 1차 인증 후 모바일 OTP로 인증하는 것과 같이, 여러 종류의 인증 수단을 조합하여 인증하는 방식이 이에 해당한다.
- 주요 동작 흐름은 다음과 같다.
	- 서비스에 계정 정보로 1차 인증시, 추가 인증 수단으로의 인증을 사용자에게 요구한다.
	- 추가 인증 수단의 인증까지 마치면, 사용자의 서비스 접근을 허용한다.
- 비밀번호를 탈취당하더라도, 계정의 탈취 위험을 크게 낮출 수 있어 보안이 강화되는 이점이 있다.

<br>


# OAuth 2.0 (Open Authorization 2.0)  
![](3_oauth_waifu2x_x2_n-1.webp)

- 사용자가 비밀번호를 제공하지 않고도, 이용하려는 서비스에 접근 권한을 위임시켜주는 인가 **프레임워크**이다.
- 여러 서비스 이용시 구글 계정이나 카카오톡 계정으로 해당 서비스의 이용을 가능하게 하는 기능을 제공하는 경우, OAuth를 기반으로 하는 OIDC를 구현하여 서비스를 제공한 경우라 볼 수 있다.
- OAuth를 구현한 서비스에서의 주요 동작 흐름은 다음과 같다.
	- 사용자가 서비스에 접속, '구글 계정으로 이용'과 같이 인증 서비스를 이용해 해당 서비스를 이용하길 희망하는 경우, 해당 인증 서비스로 사용자를 이동시킨다.
	- 사용자는 인증 서비스에 로그인후, 이용하려는 서비스에 권한을 제공함을 동의한다.
	- 인증, 동의 성공시 인증 서비스에서 이용하려는 서비스에 임시 인증 코드를 전달한다.
	- 이용하려는 서비스에서는 전달 받은 임시 인증 코드를 인증 서비스의 서버로 전달, Access Token을 발급후 사용자 정보를 가져온다.
- 사용자의 비밀번호나 개인 정보가 아닌 권한만 서비스에 제공하기에, 사용자가 서비스에 제공한 권한을 편리하게 관리할 수 있다.

<br>


# SAML (Security Assertion Markup Language)  
![](4_saml_waifu2x_x2_n-1.webp)

- XML을 기반으로 SSO를 구현, 인증 정보를 교환하기 위한 **프로토콜**이다.
- Slack, Zoom과 같은 협업 툴에서 사내 계정 로그인시, 사내 계정으로 인증하여 해당 서비스에 로그인이 가능한 경우가 이에 해당한다.
- 주요 동작 흐름은 다음과 같다.
	- 사용자가이용하려는 서비스에 접속후 로그인시, 이용하려는 서비스는 SAML 인증 요청서를 생성해, 사용자를 인증 서비스로 이동시킨다.
	- 사용자는 사내 인증 서비스와 같은 인증 서비스에 로그인하여 사용자 자신임을 인증한다.
	- 인증 서비스는 사용자를 증명하는 서명이 포함된 SAML 문서를 생성하여, 이용하려는 서비스로 사용자를 이동시킨다.
	- 이용하려는 서비스는 SAML 문서를 전달받고, 서명을 검증하여 사용자의 서비스 접근을 허용한다.
- B2B와 SaaS에서 많이 사용되어 검증된 프로토콜이라는 이점이 있다.

<br>


# LDAP (Lightweight Directory Access Protocol)
![](5_ldap_waifu2x_x2_n-1.webp)

- 사용자 정보, 그룹 정보, 조직 정보 등의 디렉토리 정보를 사용, 관리하기 위한 **프로토콜**이다.
- 사내 그룹웨어나 NAS등에 로그인시 인증 과정에서 LDAP와 같은 프로토콜이 이용된다.
- 주요 동작 흐름은 다음과 같다.
	- 사용자가 이용하려는 서비스에 로그인시 해당 서비스는 LDAP 서버에 접속하고, 로그인한 사용자의 정보를 검색한다.
	- 검색 완료시 LDAP 서버는, 해당 사용자의 정보가 어느 계층, 어느 위치에 있는지 경로 정보를 반환한다.
	- 이용하려는 서비스는 경로 정보와 사용자의 계정 정보를 이용해 LDAP 서버에 다시 접속한다.
	- LDAP 서버는 경로 정보와 계정 정보를 이용해 사용자를 검증하고, 검증 완료시 사용자의 증명 확인 결과를 이용하려는 서비스에 반환한다.
	- 이용하려는 서비스는 증명 확인 결과를 확인하여, 사용자의 서비스 접근을 허용한다.
- 사용자, 그룹, 조직 정보를 중앙에서 일관되게 관리할 수 있으며, 계층적 조회가 용이하다는 이점이 있다.
