- 4장 코드 이해_후기
	- 코드 수정시에는 코드를 읽고 이해하는데 굉장히 많은 시간이 쓰인다.
	- 코드를 '읽고 이해하는 개인의 피지컬'과 '가독성 높은 코드' 두 가지 조건이 코드 이해에 있어서 핵심적이다.
	- UML, 시퀀스 다이어그램, 클래스 다이어그램, 상태 다이어그램과 같은 시각화 도구를 통해 코드의 이해를 도울 수 있다.
		- UML은 전반적인 실행 흐름을 파악할 수 있다.
		- 시퀀스 다이어그램은 런타임 (시간)을 중심으로 구성 요소간의 상호작용을 효율적으로 파악할 수 있다.
		- 클래스 다이어그램은 정적인 상태의 구조를 이해시 유용하다.
		- 상태 다이어그램은 상태 변화에 따른 영향을 파악하는데 유용하다.
	- 이름을 통해 의미, 의도, 목적의 유추가 쉬워질수록 코드의 가독성이 향상된다
	- 메서드는 파라미터 값의 변경이 적어야한다.
		- 가령 여러 메서드가 동일한 클래스 타입을 받아 사용하는 경우, 해당 메서드에서 사용하는 클래스의 필드를 알아내려 하거나, 클래스에서 불필요한 필드를 삭제하려 할 때, 메서드의 모든 코드를 확인해야 하는 비효율이 발생한다.
		- 따라서 메서드 호출에 필요한 값을 파라미터로 전달하는 것이 코드 유지보수에 좋다.
	- 코드를 읽던 중, 메서드 호출등으로 인해 해당 메서드로 이동시 흐름이 끊길 수 있고, 반대로 너무 길어지는 경우 분석이 어려운 문제가 있다.
		- 이럴 경우 개념 단위로 메서드를 분리하고, 호출부에서 어떻게 처리되는지 대략적으로 알 수 있게 메서드명을 짓는다.


- 5장 응집도, 결합도_후기
	- 좋은 설계는 일반적으로 낮은 결합도와 높은 응집도를 추구한다.
		- 모듈이 서로 의존하는 정도가 낮고, 관련 요소가 한 곳에 모인 정도가 높아야 한다.
		- 서로 다른 역할을 하는 코드가 한 곳에 섞여있으면 응집도는 낮아지고, 분석 시간은 길어지며, 수정 비용도 높아진다.
		- 이 경우 캡슐화와 같은 방법을 통해 직접 접근을 최소화하고, 외부에 기능을 제공하는 형태로 변경하여, 수정할 범위를 최소화한다.
		- 하나의 모듈을 수정시, 다른 모듈에까지 영향이 가는 경우 결합도가 높아진다.
		- 높은 결합도는 추상화 타입이나 이벤트와 같은 방법을 적용해 간접 접근으로 처리하거나, 구현을 분리하여 응집도를 높여 해결할 수 있다.


- 6장 리팩토링_후기
	- 코드에 지속적으로 수정사항을 반영하고 구현을 추가하는 경우, 코드 수정에 따른 비용이 높아지는 시점에 도달할 수 있다.
	- 이 경우 리팩토링을 통해 코드 가독성을 높이고, 구현 변경과 확장을 용이하게 해야한다.
	- 리팩토링시에는 기존과 동일한 동작을 확인하기 위해 테스트 코드를 작성, 부분적으로 동일한 동작이 확인되는지를 검증하며 진행하는 것이 중요하다.
	- 리팩토링의 방법에는 다양한 기법이 존재하나 현재와 동일한 동작을 보장하면서도, 코드 가독성을 높이는 것이 그 목표라 할 수 있다.
	- 리팩토링 기준이나 방법은 사내 문화에 따라 다르겠지만, 수정 비용과 코드 가독성을 기준으로 판단해가며 진행하는 것이 바람직해보인다.
	- 알 수 없는 매직 넘버가 있는 경우, 주로 심볼릭 상수로 대체한다.
	- 변수와 메서드는 이름의 의미가 잘 드러나도록 변경한다.
	- 관련 코드는 묶어서 별도의 메서드로 분리한다.
	- 코드가 길어지고 로컬 변수를 자주 사용시에는 클래스로 별도 추출하는 것이 유지보수 측면에서 좋을 수 있다.
	- 클래스에 기능이 많은 경우에도 별도의 클래스로 분리하는 것이 좋을 수도 있다.
	- 파라미터는 이전의 언급과 같이, 메서드 호출에 필요한 값을 전달할 수 있게 수정한다.
	- 리팩토링 비용이 과하게 커지면 일부 기능을 마이크로서비스로 분리하는 등, 새로 구현하는 것 또한 고려 대상이 될 수 있다.
